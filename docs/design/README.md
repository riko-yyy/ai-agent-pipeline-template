# 設計ドキュメント (Design Doc)

## 運用ルール

- コーディングを指示する起点はこのディレクトリ。設計ドキュメントでもドメインモデルでも
  なく、**受け入れ条件**が実装エージェントへの実質的な指示になる
- `0000-template.md` をコピーして `docs/design/0001-xxx.md` のように追加する
- 人がレビューし承認したらマージする。このマージ自体が実装トリガーになる
  (design-doc-pipeline.yml、OVERVIEW.md参照)。ブランチ保護で必須レビューを
  設定しておくこと(SETUP.md参照)
- 受け入れ条件は検証可能な形で書く。曖昧な形容詞(「使いやすく」等)は避け、
  「入力Xのとき出力Yになる」という形にする。これがreviewer/verifier subagentの
  検証基準にもなる
